# axle — OpenAPI 3.1 for Dart Servers

**Status:** authoritative design and roadmap
**Date:** 2026-10-23
**Supersedes:** `dart-openapi-design.md` where decisions conflict. The original file remains useful as historical exploration.
**Scope:** server-side Dart only. Relic and Shelf adapters. Framework-agnostic core.

---

## 0. Summary

axle generates and serves OpenAPI 3.1 contracts for Dart HTTP servers.

A CLI (`axle`) statically analyzes annotated top-level handlers and DTO classes, then writes:

- `openapi.json` for tooling, clients, and diffs.
- `openapi.yaml`, derived from the same output path, for YAML-based tooling.
- `assets/swagger-ui/`, self-hosted Swagger UI assets for local serving.
- `lib/src/generated/openapi.g.dart`, an AOT-safe Dart constant for serving.

Thin adapters (`axle_relic`, `axle_shelf`) serve the generated spec and Swagger UI. Shared route, title, cache, and HTML behavior lives in `AxleDocs` in `axle_core`.

The core is framework-agnostic. axle documents APIs; it does not route, validate, serialize, or enforce auth.

---

## 1. What OpenAPI Is For

OpenAPI is a **contract description**, not an implementation. It is useful for:

1. Human documentation through Swagger UI or ReDoc.
2. Typed client/SDK generation.
3. Contract linting and review.
4. Mock servers generated from examples and schemas.
5. API catalogs, gateways, and developer portals.
6. Detecting accidental API changes by diffing the generated spec.

It is **not**:

- an auth system,
- a router,
- a request validator by itself,
- a serializer,
- a runtime registry,
- a substitute for Relic middleware or application validation.

axle should produce a trustworthy contract and stay out of runtime behavior it does not own.

## 2. Non-Goals for v0.1

- Auth enforcement or security-scheme metadata.
- Request/response validation.
- Runtime route discovery.
- Route discovery from Relic internals.
- Server URL configuration in `axle.yaml`.
- Swagger UI URL configuration in `axle.yaml`.
- Top-level tag descriptions in `axle.yaml`.
- Dart Frog adapter. Serverpod is covered in Phase 2.
- Class/method endpoint discovery.
- Build runner integration.
- Multiple specs per package.
- Example tests.

## 3. Architecture

### 3.1 `axle_core`

Owns the contract language:

- Annotations for routes, parameters, bodies, responses, schemas, and properties.
- OpenAPI 3.1 document model.
- JSON Schema model and helpers.
- Swagger UI HTML generation with a pinned default version and SRI hashes.
- `AxleDocs`, the framework-neutral adapter payload.
- Shared value objects.

Must not import Relic, Shelf, Serverpod, or Dart Frog.

### 3.2 `axle_cli`

Owns the compiler:

- Reads `axle.yaml`.
- Scans Dart source with `package:analyzer`.
- Resolves `Type` literals and DTO fields.
- Validates documented paths, parameters, schemas, and refs.
- Emits `openapi.json`, `openapi.yaml`, the Swagger UI asset directory, and the Dart constant.
- Provides `axle init`, `axle gen`, and `axle gen --check`.

Must not import a framework adapter. It may depend on `axle_core` for the document model and annotations.

### 3.3 `axle_relic`

Owns the Relic runtime adapter:

- Mounts the generated spec at a route.
- Serves Swagger UI at a route.
- Maps `AxleDocs` values to Relic responses and headers.
- Standalone handlers for custom routing.
- Optional local Swagger UI assets generated by `axle gen` and mounted from a directory.
- Re-exports `axle_core` so Relic apps only need one runtime dependency.

Must not contain generation logic, route discovery, or auth.

### 3.4 `axle_shelf`

Owns the Shelf adapter:

- Composable `axleDocsHandler`.
- Standalone spec/UI handlers.
- Optional local Swagger UI asset handler for the generated directory.
- No generation logic.

### 3.5 Future adapters

`axle_serverpod` and `axle_dart_frog` follow the same shape: serve a string/bytes
artifact and provide framework-specific mounting. They do not generate specs.

### Dependency direction

```
axle_core
   ^        ^          ^
   |        |          |
axle_cli  axle_relic  axle_shelf
              ^          ^
              |          |
            apps       apps
```

No reverse dependencies. `axle_core` has no framework dependency. `axle_cli` has no adapter dependency. Adapters re-export `axle_core` only when it improves the app's import story.

## 5. Locked Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Generation model | CLI + static analysis | AOT-safe, no runtime registry, predictable CI artifact |
| Annotation location | Top-level handler functions and DTO classes | Analyzer can resolve them reliably; closures cannot carry metadata |
| Type mapping | Annotations carry `Type` literals plus nullable/optional flags | `UserDto?` is not valid Dart as a type literal |
| Output | `openapi.json` + `openapi.yaml` + Swagger UI assets + Dart `const` | Tooling artifacts, self-hosted docs, and AOT-safe serving |
| Framework order | Relic, then Shelf | Concrete adapters validate the design before generalizing |
| Config source | `axle.yaml` + annotations | YAML owns global contract identity; code owns route/type facts |
| Swagger UI | Core HTML helper + adapter routes | Shared across adapters |
| Example tests | None for now | Keep the example a clean integration demo |
| Security | Deferred | Do not declare auth that axle does not enforce |

### Why not build_runner

- Not needed for the CLI-first model.
- Adds `build.yaml`, generator lifecycle, and analyzer/source_gen version coupling.
- The CLI can scan the same source and produce all artifacts.
- A future build_runner mode can reuse the analyzer layer if needed.

### Why not a runtime registry

- Relic/Shelf routers do not expose a public route list.
- No `dart:mirrors` in AOT.
- Runtime registration tends to duplicate route metadata and drift.

### Why not mixins for self-generating annotations

Dart has no macros or runtime reflection for this. A mixin can only:

- act as a marker (`class UserDto with ApiDto`) so the CLI infers fields by convention, or
- provide runtime behavior (`toJson`, validation), which the generator cannot execute.

Annotations remain the correct mechanism for route metadata and explicit schema overrides. A marker mixin for DTOs is a possible later convenience, not a replacement.

## 6. Target `axle.yaml`

YAML owns only global contract identity and compiler settings.

```yaml
openapi: 3.1.0

info:
  title: Todo API
  version: 0.1.0
  description: A Relic Todo API.
  contact:
    name: Example
    email: dev@example.com
  license:
    name: MIT

generate:
  scan:
    - lib
  output:
    json: openapi.json
    dart: lib/src/generated/openapi.g.dart
```

### Rules

- `gen` reads only `axle.yaml`, never `pubspec.yaml`.
- `init` reads `pubspec.yaml` once to seed `info.title` and `info.version`.
- After `init`, `axle.yaml` is authoritative.
- Unknown keys are errors.
- `scan` paths and output paths must stay inside the project root by default.
- `generate.scan` supports one or more directories or files.
- `generate.output.json`, `generate.output.ui`, and `generate.output.dart` are paths relative to the project root, or absolute paths inside it.
- `openapi.yaml` is derived by replacing the JSON extension with `.yaml`; there is no separate YAML setting.
- `info` maps to the OpenAPI Info Object.
- `openapi` must be a supported 3.1.x version.
- No `servers`, `docs`, `swagger_ui_url`, `tags`, or `security` in YAML.

### Why no `servers`

Relic owns the host and port. Duplicating a server URL in axle creates runtime drift. Swagger UI will use the current origin when no servers are declared.

If explicit deployment servers become necessary later, add an opt-in advanced field; do not make it a default.

### Why no `docs`

Docs routing and UI title are runtime adapter concerns:

- `mountAxleDocs` owns default paths.
- The UI title comes from the generated spec’s `info.title`.
- The Swagger UI asset URL defaults to a pinned `defaultSwaggerUiUrl` with SRI hashes in `axle_core`; `axle gen` writes local assets for adapters that accept `swaggerUiDirectory`.

No duplicated title or URL in YAML.

### Why no `tags`

Tags belong on `@ApiRoute(tags: [...])` because they are operation-local. Top-level tag descriptions are optional OpenAPI metadata and can be added later as an explicit feature.

### Why no `security`

Security is a real OpenAPI feature, but it requires:

1. A scheme registry.
2. A truthful mapping from routes to schemes.
3. Runtime middleware that actually enforces it.

axle currently does none of these. Emitting security metadata without enforcement would create a false contract.

## 7. Annotation Surface

### `@ApiRoute`

Fields:

- `method` — `ApiMethod`
- `path` — Relic or OpenAPI path syntax
- `summary`
- `description`
- `operationId` — defaults to the handler function name
- `tags`
- `deprecated`
- `pathParams`
- `queryParams`
- `headerParams`
- `body`
- `responses`
- `ignore`

Repeated annotations are allowed. Set a unique `operationId` when annotating the same handler more than once.

### Parameters

- `ApiPathParam(name, type: ...)`
- `ApiQueryParam(name, type: ..., required: ...)`
- `ApiHeaderParam(name, type: ..., required: ...)`

Parameters carry a Dart `Type` literal, not a nullable type literal. Nullability is expressed with `ApiResponse(nullable: true)` or by the Dart field type for DTOs.

### Body and responses

- `ApiBody(type: ...)`
- `ApiResponse(status: ..., type: ..., nullable: ...)`
- Convenience constructors: `ApiResponse.ok`, `created`, `noContent`, `badRequest`, `notFound`, `internalServerError`

### Schemas and properties

- `@ApiSchema(name: ..., description: ..., ignore: ...)` on classes.
- `@ApiProperty(name: ..., description: ..., example: ..., required: ..., ignore: ...)` on fields.
- `@JsonKey(name: ...)` is read when the project depends on `json_annotation`.

### Naming defaults

- Schema name = class name unless `@ApiSchema(name:)`.
- Operation ID = handler function name unless `@ApiRoute(operationId:)`.
- JSON property name = Dart field name unless `@ApiProperty(name:)` or `@JsonKey(name:)`.

Overrides are optional and should be used only for stable public contracts.

## 8. DTO Inference Rules

### Supported mappings

| Dart | JSON Schema |
|---|---|
| `int` | `integer` |
| `double`, `num` | `number` |
| `bool` | `boolean` |
| `String` | `string` |
| `DateTime` | `string` / `date-time` |
| `Uri` | `string` / `uri` |
| `Duration` | `string` / `duration` |
| `BigInt` | `integer` / `int64` |
| `Uint8List`, `ByteData` | `string` / `byte` |
| `List<T>`, `Set<T>`, `Iterable<T>` | `array` with `items` |
| `Map<String, T>` | `object` with `additionalProperties` |
| enum | `string` with enum values |
| class | `$ref` to a component schema |
| `dynamic`, `Object` | unconstrained schema |
| nullable type | `type: [..., "null"]` or `anyOf` for refs |

### Property rules

- Public instance fields only.
- Private and static fields are skipped.
- Inherited fields are included.
- Fields with `@ApiProperty(ignore: true)` are skipped.
- Fields with both `includeToJson: false` and `includeFromJson: false` are skipped.
- Non-nullable fields are required unless `@ApiProperty(required: false)` or a `JsonKey.defaultValue` says otherwise.
- Doc comments become property descriptions unless overridden.
- Duplicate JSON property names are errors.

### Unsupported for now

- Generic DTO classes.
- Type parameters in fields.
- Records.
- Function types.
- Mixins as DTO types.
- Custom `JsonValue` / `JsonEnum` serialization.
- Global `json_serializable` field rename rules.
- Polymorphic/sealed-class schemas.
- `oneOf`/`allOf`/`discriminator` generation from class hierarchies.

These are documented limitations, not silent guesses.

## 9. CLI Contract

### Global installation

```sh
dart pub global activate --source path packages/axle_cli
axle init
axle gen
axle gen --check
```

### Local invocation

```sh
dart run axle_cli:axle init
dart run axle_cli:axle gen
```

`axle_cli` must be resolvable as a dev dependency for `dart run` to work.

### `axle init`

```
axle init [--project <dir>] [--force]
```

- Reads `pubspec.yaml` to seed title and version.
- Writes `axle.yaml`.
- Does not edit `pubspec.yaml` or `server.dart`.
- Refuses to overwrite without `--force`.
- Prints adapter-neutral setup guidance; no framework package is assumed.
- Removed flags: `--title`, `--version`, `--docs-path`, `--spec-path`.

### `axle gen`

```
axle gen [--project <dir>] [--config axle.yaml] [--check] [--verbose]
```

- Reads only `axle.yaml` and Dart source.
- Writes JSON, YAML, and Dart artifacts.
- `--check` fails when any of the three artifacts is stale.
- Prints warnings to stderr.
- Exit codes follow sysexits: usage `64`, data `65`, software `70`, config `78`.

### Generated artifacts

- `openapi.json` — pretty, deterministic, trailing newline.
- `openapi.yaml` — YAML block form derived from the JSON path, stable and parseable.
- `assets/swagger-ui/` — Swagger UI 5.34.0 static assets for local serving.
- `openapi.g.dart` — `const String axleOpenApiJson`, format-stable, no runtime file I/O.

## 10. Runtime Adapter Contract

`axle_relic` exposes:

```dart
app.mountAxleDocs(
  spec: axleOpenApiJson,
  docsPath: '/docs',        // optional
  specPath: '/openapi.json',// optional
  title: 'Todo API Docs',   // optional
  swaggerUiUrl: '...',      // optional
  swaggerUiDirectory: 'assets/swagger-ui', // optional local assets
  swaggerUiPath: '/docs-assets', // optional local asset prefix
  noCache: true,            // optional
);
```

Defaults:

- `docsPath = '/docs'`
- `specPath = '/openapi.json'`
- `title` derived from the spec’s `info.title`, falling back to `API Docs`
- `swaggerUiUrl = defaultSwaggerUiUrl` from `axle_core`
- `noCache = true`

Standalone handlers:

```dart
openApiJsonHandler(spec)
swaggerUiHandler(specPath: '/openapi.json')
```

No auth, route discovery, or generation belongs here.

## 11. Security: Deferred Design Hook

Security is intentionally out of scope for v0.1.

When it is added, the clean design is:

- `@ApiRoute(security: ['bearerAuth'])` on protected handlers.
- `security: []` to make one operation public.
- `null` to inherit a global default.
- A scheme registry supplied by annotations or adapter configuration.
- `axle gen` validates that every referenced scheme exists.
- Runtime middleware is still implemented by the application/adapter, not generated by axle.

Do not add security to `axle.yaml` until axle can truthfully represent and validate it.

#### `axle_serverpod` plan

Serverpod exposes two HTTP surfaces; only one is documentable as REST:

- **API-server endpoints** (`Endpoint` subclasses) speak the binary Serverpod
  protocol over POST. No HTTP method semantics, no status codes. Describing
  them in OpenAPI would be fiction — explicitly out of scope, permanently.
- **Web-server routes** (`Route` subclasses via `pod.webServer.addRoute`) are
  real HTTP: method filtering with automatic 405s, `:param` segments,
  wildcards, startup conflict detection. Primitives are Relic-derived
  (`Body.fromString`, `MimeType`, `Response.ok`). This is the adapter surface.

Serve-only, mirroring the adapter contract — no core or CLI changes:

```dart
pod.webServer.addRoute(
  AxleDocsRoute(
    spec: axleOpenApiJson,
    swaggerUiDirectory: 'assets/swagger-ui',
  ),
  '/docs',
);
```

- Implemented as `WebServer.mountAxleDocs`: `AxleOpenApiRoute` serves the spec,
  `AxleDocsRoute` serves the UI, and `StaticRoute.directory` serves local assets.
  Paths stay absolute (`/openapi.json`, `/docs`, `/docs-assets` by default), so
  the UI's spec URL is correct regardless of mount points.
- `AxleDocs` keeps owning paths, title, cache, and HTML; the routes only
  translate. Re-export `axle_core` like the other adapters.
- Local UI assets use Serverpod's `StaticRoute`; Relic's static handler resolves
  files from `remainingPath` and rejects traversal outside the root. The
  adapter validates the directory exists before registering routes.
- Docs serve from the **web server port**, not the API server port — the
  adapter README states this explicitly.

Generation gap: `axle gen` discovers `@ApiRoute` on top-level functions, but
Serverpod REST handlers are `handleCall` methods on `Route` subclasses.
Chosen pattern (no core changes): annotate a top-level function, delegate
from a thin `Route` class, register the same path in `addRoute`. Derive the
`addRoute` path and the annotation path from a shared constant — the two
strings can otherwise drift (accepted Swaggo-model cost). Method discovery in
core (option B) stays deferred until a second framework demands it; it must
not be un-deferred for one adapter.

Effort: comparable to `axle_shelf`. `StaticRoute` traversal behavior was
verified in the Relic 2.0 static handler before implementation.

The adapter requires Serverpod 4.x, which uses Relic 2.x. `axle_relic` moved
from Relic 1.2.0 to 2.0.0-rc.2 so the workspace resolves one Relic major.

## 14. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Analyzer API churn | Pin a tested range; support latest stable Dart; keep scanner isolated |
| Annotation/route drift | Annotations live next to handlers; add contract tests later |
| YAML drift | Strict schema, unknown-key errors, no duplicated runtime fields |
| Runtime config drift | Relic owns host/port; axle owns no servers |
| Security drift | Do not emit security until enforcement exists |
| Path traversal in config | Reject scan/output paths outside project root |
| Path deps block publishing | Phase 4 replaces path deps with versions |
| Relic API changes | Keep adapter tiny; test against pinned Relic 2.0.0-rc.2 |
| Serverpod shape mismatch | Separate adapter; do not contort core |
| CDN dependency | `axle gen` emits local Swagger UI assets; adapters accept `swaggerUiDirectory` |
| Drift from `json_serializable` | Document supported subset; add global field-rename support later |
