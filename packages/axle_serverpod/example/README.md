# axle_serverpod example

A Docker-free Serverpod "mini" app that serves a generated OpenAPI document and
Swagger UI with `axle_serverpod`.

## What it shows

- An annotated top-level handler in `lib/src/api/greeting_api.dart` that calls
  the generated `GreetingEndpoint.hello` method.
- The generated `Greeting` model mapped into `components.schemas` — `message`,
  `author`, and `timestamp` (`date-time`), all required.
- A thin Serverpod `Route` subclass that delegates to the handler, with the
  annotation path and `addRoute` path sharing one constant.
- `pod.webServer.mountAxleDocs(...)` serving the spec, UI, and local assets.
- Generated `openapi.json`, `openapi.yaml`, `openapi.g.dart`, and Swagger UI
  assets committed alongside the source.

```
axle_serverpod_example_server/
  lib/server.dart              # route registration + mountAxleDocs
  lib/src/api/greeting_api.dart # annotation, handler, Route subclass
  lib/src/axle/openapi.g.dart   # generated Dart spec constant
  lib/src/greetings/           # generated Serverpod GreetingEndpoint + model
  axle.yaml                    # generator configuration
  openapi.json / openapi.yaml  # generated artifacts
  assets/swagger-ui/           # generated local UI assets
```

## Run

Requires Dart 3.12.2 or newer. No database, Redis, or Docker is used.

```sh
cd packages/axle_serverpod/example
dart pub get

cd axle_serverpod_example_server
dart run axle_cli:axle gen --check
dart run bin/main.dart
```

The web server listens on port `8082` by default:

| URL | Result |
| --- | --- |
| <http://localhost:8082/greeting> | Greeting with the default name |
| <http://localhost:8082/greeting?name=Axle> | Greeting for a query parameter |
| <http://localhost:8082/openapi.json> | Generated OpenAPI 3.1 document |
| <http://localhost:8082/swagger> | Swagger UI |
| <http://localhost:8082/docs-assets/swagger-ui.css> | Local UI asset |

`serverpod start` shows Serverpod **Endpoint** methods in its terminal UI and
Insights. `/greeting` is a web-server `Route`, so it appears in the OpenAPI docs
at `/swagger` and the JSON spec, not in the endpoint explorer.

The development config uses API server port `8090` and Insights port `8091`
(chosen to avoid the common `8080` conflict with local Docker/OrbStack
proxies). The REST route and docs are only on the web server port `8082`.

## Regenerate

`axle gen` writes the spec, YAML, UI assets, and Dart constant:

```sh
cd axle_serverpod_example_server
dart run axle_cli:axle gen
```

`--check` fails when the committed artifacts are stale, which is what CI runs.

## Notes

- The REST route reuses the generated `GreetingEndpoint.hello` method, so the
  response is driven by the Serverpod protocol model rather than a duplicate
  DTO.
- API-server `Endpoint` methods speak the Serverpod protocol, not REST, and are
  intentionally not documented directly. The web-server `Route` wrapping the
  greeting handler is what appears in the spec.
- The `example_client` package is generated by Serverpod and is kept so
  `serverpod generate` continues to work. It is not needed to run the server.
